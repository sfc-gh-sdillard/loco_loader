# loco_loader
Loads local CoCo (for now) conversations into Snowflake for later recall and analysis

## Prerequisites

- Python 3.11+
- [Cortex Code Desktop](https://docs.snowflake.com/en/user-guide/cortex-code/cortex-code) installed (provides the `cortex` CLI)
- A Snowflake account with Cortex AI functions enabled
- A connection configured in `~/.snowflake/connections.toml` with key pair auth

### Python dependencies

```
pip install snowflake-connector-python snowflake cryptography
```

### Snowflake setup

The scripts target `DEMOS.AGENT_MEMORY`. Create the schema before first run:

```sql
CREATE SCHEMA IF NOT EXISTS DEMOS.AGENT_MEMORY;
GRANT ALL ON SCHEMA DEMOS.AGENT_MEMORY TO ROLE <your_role>;
```

### Configuration

Edit `CONNECTION_NAME` in `core.py` to match your connection name from `~/.snowflake/connections.toml`.

## Usage

### Full load (first run or rebuild)

Extracts all conversations via the `cortex` CLI, truncates both tables, inserts everything, generates summaries, and creates Cortex Search services.

```
python3 full_load.py
```

### Incremental load (ongoing sync)

Fetches only conversations updated since the last load. MERGEs conversation metadata, INSERTs new message turns, re-summarizes stale sessions, and refreshes search services.

```
python3 incremental_load.py
```

### Query

```
python3 query.py stats                              # row counts, date range, top sessions
python3 query.py conversations                       # list recent conversations
python3 query.py conversations --search "docusign"   # semantic search over summaries
python3 query.py conversations --id <session_id>     # show one session's metadata + summary
python3 query.py messages --search "iceberg"         # semantic search over message content
python3 query.py messages --id <session_id>          # all messages in a session
python3 query.py messages --role user                # filter by speaker
python3 query.py transcript --id <session_id>        # readable [USER]/[ASSISTANT] format
```

Add `--format json` to any command for JSON output. Use `-n <limit>` to control result count (default 20).

## Schema

| Table | Purpose |
|---|---|
| `CONVERSATIONS` | Session metadata, full transcript (VARIANT), AI-generated summary |
| `MESSAGES` | One row per conversation turn — searchable by content, filterable by role |

### Cortex Search Services

| Service | Indexed column | Filters |
|---|---|---|
| `MESSAGES_SEARCH` | CONTENT | SESSION_ID, ROLE |
| `CONVERSATIONS_SEARCH` | SUMMARY | TITLE, SOURCE |

## Known limitations

- The `cortex` CLI indexes conversations with a lag — active sessions won't appear until the session is saved/closed server-side
- ~5% of sessions fail to fetch (local-only sessions, malformed transcript JSON) — these are skipped
- Summaries are generated by `llama3.1-70b` via `AI_COMPLETE` and can be overly verbose
